XGBoost, one tree at a time

XGBoost makes a prediction by adding up many small decision trees. Each new tree is trained to fix the mistakes the earlier trees left behind. This guide builds that idea from scratch: first the intuition, then the five formulas that drive it, then a full model you grow tree by tree, and finally a look at which features the model relies on.

Part 1

The intuition: a relay of small corrections

A single decision tree asks a series of yes/no questions (“Is it hotter than 75°F?”, “Is it a weekend?”) and lands on an answer. If you let one tree grow very deep, it can fit the training data perfectly. It also memorizes the noise and predicts poorly on new days.

Boosting takes the opposite approach. It starts with a crude guess, usually the average. Then it repeats one loop:

  1. Measure how wrong the current prediction is for every row. These errors are called residuals.
  2. Train a small tree to predict those residuals.
  3. Add a fraction of that tree’s answer to the running prediction. The fraction is the learning rate, η (eta).

Each tree on its own is weak. It might only know “hot days sell more.” But each one is aimed squarely at what is still wrong, so the sum keeps improving.

    What makes XGBoost different from other boosting methods

    Boosting is older than XGBoost. AdaBoost (1995) and classic gradient boosting (2001) already chained weak learners together. XGBoost (2014–2016) kept the same relay but changed how each tree is built and how the whole thing runs.

    Second-order

    It uses curvature, not just slope

    Classic gradient boosting knows which direction reduces the error. XGBoost also uses how sharply the loss curves, which tells it how big a step to take. That is a Newton step instead of a plain gradient step.

    Regularized objective

    Complexity has a price

    Every tree is scored on accuracy minus a penalty. λ shrinks leaf values toward zero. γ charges a fixed cost for every extra leaf, so weak splits get pruned.

    One formula

    Splits are scored by the same objective

    The “similarity” and “gain” you will compute in Part 2 fall straight out of that penalized objective. Tree building and regularization agree by construction.

    Sparsity-aware

    Missing values have a learned path

    At each split, XGBoost tries sending missing values left and right and keeps whichever gives more gain.

    Systems

    Built to be fast

    Features are pre-sorted or binned into histograms, and the best split for each feature is searched in parallel. That is a large part of why it won so many competitions.

    Part 2

    The math, one split at a time

    For regression with squared error, the whole algorithm reduces to five lines. You only need addition, squaring and division. Read them once, then use the lab to watch each number move.

    Step 1 · Start
    ŷ₀ = average(y) = 96.2

    Every row starts with the same guess. Modern XGBoost estimates this starting point from the data.

    Step 2 · Residuals
    r = y − ŷ

    How far off each row is. Positive means we guessed too low.

    Step 3 · Similarity
    Sim = (Σ r)²n + λ

    High when a group’s residuals agree in sign. Residuals that cancel out score near zero.

    Step 4 · Gain
    Gain = SimL + SimR − Simroot

    How much a split improves agreement. Keep it only if Gain > γ; otherwise prune it.

    Step 5 · Leaf + update
    w = Σ rn + λ  ŷ ← ŷ + η·w

    Each leaf outputs a shrunken average residual. The prediction moves by η times that.

    Where the “second-order” part hides

    The general formulas use each row’s gradient g (slope of the loss) and hessian h (its curvature): Sim = G²/(H + λ) and w = −G/(H + λ), where G and H are the sums over the rows in a leaf.

    For squared error, g = ŷ − y = −r and h = 1 for every row. So G is minus the sum of residuals and H is just the count n. That is why the simple versions above use n. For classification with log loss, h = p(1 − p), so rows the model is already confident about count for less.

    The XGBoost paper also puts a factor of ½ in front of the gain. It doesn’t change which split wins, so we leave it out here.

      What just happened: because we started at the average, the 16 residuals sum to zero and the root’s similarity is 0. A good split separates the negative residuals from the positive ones, so each side becomes internally “similar” and the gain jumps. XGBoost repeats this search for every feature and every threshold, keeps the winner, and then searches again inside each branch until it hits the depth limit.

          Reading importance responsibly

          Gain is usually the most meaningful: it measures how much each feature actually improved the objective. Weight only counts how often a feature was chosen, so a noisy feature that gets picked for many tiny late-stage splits can look busy without being useful. Cover tells you how many rows those splits touched. A feature used at the root covers everyone; one used deep in a tree covers a few rows.

          Two more cautions. Importance describes what this model used, not what causes sales in the real world. And when two features carry the same information, the model may lean on one and ignore the other, so the second looks unimportant even though it isn’t. For sturdier answers, practitioners also use permutation importance (shuffle a feature and measure how much accuracy drops on held-out data) and SHAP values (split each individual prediction into per-feature contributions, much like the breakdown you saw in Lab B).

          Library note: in the Python scikit-learn wrapper, model.feature_importances_ reports average gain per split by default. Use booster.get_score(importance_type="total_gain") for the total.

from xgboost import XGBRegressor

model = XGBRegressor(
    n_estimators=300,
    learning_rate=0.1,    # η
    max_depth=4,
    reg_lambda=1.0,       # λ
    gamma=0.0,            # γ
    subsample=0.8,
    colsample_bytree=0.8,
    early_stopping_rounds=30,
)
model.fit(X_train, y_train, eval_set=[(X_valid, y_valid)], verbose=False)

model.feature_importances_                                   # average gain per split
